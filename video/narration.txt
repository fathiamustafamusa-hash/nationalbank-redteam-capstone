The headline: our team achieved full compromise of the lab environment in under fifteen minutes. No zero-days. No advanced tooling. Just public exploits, default credentials, and one phishing email.

We identified twenty-two findings. Five are critical, and these are the ones that directly led to compromise. First: a database backup file left in the web root exposed full database credentials. Third: the API had no authentication check on its admin endpoint, so anyone could access it. And API SQL injection bypassed login entirely. Fourth: broken object level authorization let us read any user record by simply changing an ID in the URL. Fifth: a phishing email from a spoofed internal address was delivered and clicked, and credentials were captured by our credential harvesting portal. On top of those, twelve high severity issues, including cross-user data leaks, SSRF that read internal system files, unrestricted file upload, missing security headers, and outdated software across the stack.

Our attack chain looked like this. Step one: phishing email from it-support at nationalbank dot com. The target clicked, credentials captured. Step two: we used API broken authentication to reach the admin panel without a token. Step three: BOLA let us enumerate every user and their API keys. Step four: mass assignment let us register a new account with the admin role. Step five: SQL injection and command injection gave us a root shell on the server. Step six: SSRF read internal files, and the exposed backup file leaked the database password. The whole chain ran in under fifteen minutes with beginner level skill. Public exploit references were all we needed. We also tested detection evasion. Signature-only antivirus was bypassed by custom byte-level obfuscation. The commercial encoder we tried was actually detected because of its own signature, proving that signature-only antivirus is not enough.

If this were production, every customer record could be extracted via SQL injection. Any user account could be accessed or taken over. The web server could be fully controlled by an attacker. Internal files including system configuration could be read remotely. Fraudulent transactions and regulatory exposure would be immediate. For a bank of five thousand employees under RBI and PCI-DSS obligations, this is not just an IT incident. It is a compliance and reputation crisis.
